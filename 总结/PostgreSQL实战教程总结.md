## 一、基础查询、CRUD 与 `RETURNING`（第 1–2 节）

### 1.1 命名规范与建删表
- **命名惯例**：表名用复数 + `snake_case`，列名用 `snake_case`；关键字大小写不敏感。
- **默认值列命名**：计算列未指定别名时，PG 默认命名为 `?column?`。
- **删表级联**：被其他表外键引用的表直接 `DROP TABLE` 会报错，需使用 `DROP TABLE [IF EXISTS] tbl CASCADE;`。

### 1.2 字符串拼接
- `s1 || s2`：PG 标准拼接运算符。
- `CONCAT(s1, s2, ...)`：拼接多个字符串。
- `CONCAT_WS(sep, s1, s2, ...)`：按分隔符 `sep` 拼接。

### 1.3 `WHERE` 求值顺序与 `RETURNING`
- **求值顺序**：`FROM` → `WHERE` → `SELECT` → `ORDER BY`。**`WHERE` 中不可引用 `SELECT` 别名**，而 `ORDER BY` 中可以。
- **范围与列表**：`BETWEEN low AND high` 为闭区间；`!=` 与 `<>` 完全等价。
- **PG 特有 `RETURNING`**：`INSERT` / `UPDATE` / `DELETE` 末尾均可加 `RETURNING * | col1, col2`，直接返回受影响行（无需再发 `SELECT`）。
  ```sql
  INSERT INTO products (name, price) VALUES ('Pen', 5.0) RETURNING id;
  UPDATE products SET price = price * 1.1 WHERE id = 1 RETURNING *;
  DELETE FROM products WHERE id = 1 RETURNING id, name;
  ```
- **防误操作**：`UPDATE` / `DELETE` 省略 `WHERE` 会修改/清空全表。

## 二、表约束与关系设计（第 3 节）

1. **三值逻辑与 `NOT NULL`**：`NULL` 不等于 `''` 或 `0`；`NULL = NULL` 结果为 `NULL`。判断空值必须用 `IS NULL` / `IS NOT NULL`（`psql` 下可用 `\pset null NULL` 显示空值）。
2. **`DEFAULT`**：常用 `created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP`；`INSERT` 时省略该列或传 `DEFAULT` 触发。
3. **`CHECK` 约束**：
   ```sql
   CREATE TABLE items (
     price DEC CHECK (price > 0),
     discount DEC,
     CONSTRAINT chk_price CHECK (discount < price) -- 表级约束可引用本表多列，不可跨表
   );
   ```
   - 已有表 `ALTER TABLE ... ADD CONSTRAINT ... CHECK (...)` 时，若有历史行不满足会直接报错。
4. **`PRIMARY KEY` 与自增推荐**：隐式包含 `UNIQUE + NOT NULL`。**教程明确不推荐 `SERIAL`**（权限与完整性缺陷），推荐使用 SQL 标准**标识列**：
   ```sql
   id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY
   -- 或允许显式指定值的 GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
   ```
5. **`UNIQUE`**：默认约束名 `{table}_{col}_key`。PG 中 **`NULL` 与 `NULL` 不相等，可空 `UNIQUE` 列允许多个 `NULL`**（除非建唯一索引时显式声明 `NULLS NOT DISTINCT`）。
6. **`FOREIGN KEY`**：`1:N` 外键建在“多”的一方（习惯命名 `{父表单数}_id`）；`M:N` 拆连接表；支持自引用外键。
   - `ON DELETE` 动作：`NO ACTION`（默认）/ `RESTRICT`（有子行则报错）、`SET NULL`（子外键列须可空）、`CASCADE`（级联删除子行）、`SET DEFAULT`。

## 三、排序、分页、`NULL` 与连接查询（第 4–5 节）

### 3.1 `ORDER BY`、`LIMIT` 与 `FETCH`
- **`NULL` 排序控制**：`ORDER BY col [ASC | DESC] [NULLS FIRST | NULLS LAST]`。
- **`LIMIT` 与 `OFFSET`**：必须配合 `ORDER BY` 使用，否则顺序不确定；分页公式 `LIMIT page_size OFFSET page_size * (page_no - 1)`。
- **SQL:2008 标准 `FETCH`**（跨库可移植性优于 `LIMIT`）：
  ```sql
  SELECT * FROM tbl ORDER BY id
  OFFSET 10 ROWS
  FETCH NEXT 5 ROWS ONLY; -- FIRST 与 NEXT 同义，ROW 与 ROWS 同义；省略行数默认 1
  ```

### 3.2 `JOIN` 家族
- **同名列简写**：两表同名列等值连接可用 `USING (col)` 替代 `ON t1.col = t2.col`。多表存在同名列必须加表名/别名限定。
- **连接类型**：`INNER JOIN`、`LEFT JOIN`、`RIGHT JOIN`、`FULL [OUTER] JOIN`（保留双边未匹配行，缺侧填 `NULL`）、`CROSS JOIN`（等价 `FROM t1, t2` 笛卡尔积）。
- **自连接**：同一表引用多次必须赋不同别名；树形层级保留根节点（`parent_id IS NULL`）须用 `LEFT JOIN`。
- **`NATURAL JOIN` 两大陷阱**：
  1. 无同名列时自动退化为 `CROSS JOIN`（笛卡尔积）；
  2. 将两表**所有**同名列同时作为 `AND` 条件，表结构增删同名列会静默改变连接逻辑，生产慎用。

## 四、分组聚合与集合运算（第 6–7 节）

### 4.1 `GROUP BY`、`HAVING` 与多维分组
- **求值顺序**：`FROM` → `GROUP BY` → `HAVING` → `SELECT` → `ORDER BY`（故 **`HAVING` 中不可引用 `SELECT` 别名**；`SELECT` 中所有非聚合列必须出现在 `GROUP BY` 中）。
- **单条 SQL 多维汇总**：
  - `GROUP BY GROUPING SETS ((c1, c2), (c1), (c2), ())`：仅计算显式列出的分组，`()` 代表总计。
  - `GROUP BY ROLLUP (c1, c2)`：按层级生成 `(c1, c2)`、`(c1)`、`()`（列顺序决定小计层级）。
  - `GROUP BY CUBE (c1, c2)`：生成全部组合 `(c1, c2)`、`(c1)`、`(c2)`、`()`。
  - **`GROUPING(col)`**：返回 `1` 表示该列在当前汇总行被折叠聚合，返回 `0` 表示为分组值（用于区分汇总产生的 `NULL` 与真实 `NULL` 数据）。

### 4.2 集合运算
- **共同约束**：各 `SELECT` 列数必须相同、对应列类型兼容；`ORDER BY` 只能放在最后一个查询末尾。
- **运算符**：
  - `UNION`（去重）/ `UNION ALL`（保留重复）
  - `INTERSECT`（交集去重）/ `INTERSECT ALL`
  - `EXCEPT`（差集：在第一结果集但不在第二结果集，**顺序敏感** `A EXCEPT B ≠ B EXCEPT A`）/ `EXCEPT ALL`

## 五、PostgreSQL 核心数据类型（第 8 节）

| 类别 | 类型 | 核心特性与边界 |
| :--- | :--- | :--- |
| **布尔** | `BOOLEAN` / `BOOL` (1B) | 三态：`true` / `false` / `NULL`。有效字面量 `true`/`'t'`/`'y'`/`'yes'`/`'1'` 与 `false`/`'f'`/`'n'`/`'no'`/`'0'`（除无引号 `true`/`false` 外均须单引号）；输出为 `t`/`f` |
| **字符** | `CHAR(n)`, `VARCHAR(n)`, `TEXT` | `CHAR(n)` 定长空格填充（`length()` 去尾空格，`octet_length()` 含填充字节）；`VARCHAR(n)` 上限 `10,485,760`；`VARCHAR` 不写 `(n)` 与 `TEXT` 性能及行为一致（上限 1GB，保留尾随空格） |
| **整数** | `SMALLINT`(2B), `INT`(4B), `BIGINT`(8B) | 范围分别为 `[-32768, 32767]`、`[-2^31, 2^31-1]`、`[-2^63, 2^63-1]`，越界报错 |
| **定点数** | `DECIMAL(p, s)` / `NUMERIC(p, s)` | `p` (`1~1000`)，`s` (`-1000~1000`)；PG 15+ 支持负标度（向小数点左侧舍入）；半数向远离零方向舍入（`2.5→3`, `-2.5→-3`）；支持 `'Infinity'`、`'-Infinity'`、`'NaN'` |
| **日期** | `DATE` (4B) | `4713 BC ~ 5874897 AD`，ISO 8601 `yyyy-mm-dd`，支持 `d + days`、`extract(year FROM d)` |
| **时间** | `TIME(p)` (8B) | `00:00:00 ~ 24:00:00`，精度 `p` (`1~6`)；`current_time` 带时区，`localtime` 不带时区 |
| **时间戳** | `TIMESTAMP` / `TIMESTAMPTZ` (8B) | `TIMESTAMP` 不存/不转换时区（默认 `LOCALTIMESTAMP`）；**`TIMESTAMPTZ` 存为 UTC，读取时按会话 `TIME ZONE` 自动转换（默认 `CURRENT_TIMESTAMP`，支持夏令时，推荐优先使用）**。两时间戳相减得 `INTERVAL`；`SET TIME ZONE 'Asia/Shanghai';` |
| **时间间隔** | `INTERVAL` | `INTERVAL '1.5 hours 30 minutes'`、`NOW() + INTERVAL '7 days'`；`JUSTIFY_HOURS()`、`JUSTIFY_DAYS()`、`JUSTIFY_INTERVAL()` 进位规整 |
| **UUID** | `UUID` (128-bit) | 主键防自增暴露数量：`id UUID PRIMARY KEY DEFAULT gen_random_uuid()` |

## 六、子查询、CTE 与去重（第 9–11 节）

### 6.1 子查询与量词
- **位置**：`WHERE`（标量/列表）、`SELECT`（标量）、`FROM`（派生表）、`JOIN`。相关子查询依赖外层列，大表建议改写为 `JOIN + GROUP BY`。
- **`EXISTS (SELECT 1 FROM ...)`**：内部用 `SELECT 1` 占位避免取列开销，判断存在性。
- **`ANY` (`SOME`) vs `ALL`**：
  - `> ANY (...)` 等价 `> MIN(...)`；`> ALL (...)` 等价 `> MAX(...)`。
  - **空结果集边界**：子查询返回 0 行时，`ALL` 恒返回 `true`，`ANY` 返回 `false`。

### 6.2 CTE 公用表表达式（`WITH`）
- **普通与数据修改 CTE**：CTE 内部可直接写 `DELETE / UPDATE / INSERT ... RETURNING *` 并把受影响行管道传给主查询：
  ```sql
  WITH moved AS (
    DELETE FROM source_tbl WHERE flag = 1 RETURNING *
  )
  INSERT INTO archive_tbl SELECT * FROM moved;
  ```
- **递归 CTE（`WITH RECURSIVE`）**：由**锚定成员**（执行 1 次）+ `UNION [ALL]` + **递归成员**（引用自身直到返回 0 行结束）组成，专治层级树遍历与序列生成。

### 6.3 `SELECT DISTINCT` 与 `DISTINCT ON`
- `SELECT DISTINCT col1, col2`：按组合去重。
- **PG 特有 `SELECT DISTINCT ON (col1)`**：按 `ON (...)` 分组并**仅保留每组第一行**。**硬性规则**：`ORDER BY` 最左列必须与 `DISTINCT ON (...)` 表达式一致，后续 `ORDER BY` 列决定保留哪一行（如 `ORDER BY product_name, quantity DESC` 取每种商品最大库存行）。

## 七、视图、物化视图与条件表达式（第 12–13 节）

### 7.1 视图与物化视图
- **普通视图**：`CREATE [OR REPLACE] VIEW v AS query;`、`DROP VIEW IF EXISTS v CASCADE;`（有依赖视图等对象时需 `CASCADE`）。不存物理数据，每次查询动态执行。
- **物化视图**：物理持久化查询结果，不随基表自动更新：
  ```sql
  CREATE MATERIALIZED VIEW [IF NOT EXISTS] mv_name AS query WITH DATA;
  REFRESH MATERIALIZED VIEW mv_name; -- 手动全量刷新数据
  DROP MATERIALIZED VIEW [IF EXISTS] mv_name [CASCADE];
  ```

### 7.2 条件表达式（PG 重点差异）
- **`CASE`**：支持搜索型（`CASE WHEN cond THEN ... END`）与简单型（`CASE expr WHEN val THEN ... END`），自上而下短路求值，无匹配且无 `ELSE` 返回 `NULL`。
- **`COALESCE(v1, v2, ...)`**：返回第一个非 `NULL` 值。
- **`NULLIF(e1, e2)`**：`e1 = e2` 返回 `NULL`，否则返回 `e1`（防除零必用：`x / NULLIF(y, 0)`）。
- **`GREATEST(e1, e2, ...)` / `LEAST(e1, e2, ...)`**：**与 SQL 标准/MySQL 不同！PG 中会忽略 `NULL` 参数，仅当所有参数全为 `NULL` 时才返回 `NULL`**。

## 八、表结构修改、序列与标识列（第 14 节）

### 8.1 `ALTER TABLE` 核心规则
```sql
ALTER TABLE tbl RENAME TO new_tbl;
ALTER TABLE tbl RENAME [COLUMN] old_col TO new_col; -- 不支持 RENAME COLUMN IF EXISTS
ALTER TABLE tbl ADD COLUMN col type [constraint];
ALTER TABLE tbl DROP COLUMN [IF EXISTS] col [CASCADE | RESTRICT];
ALTER TABLE tbl ALTER COLUMN col SET DATA TYPE new_type;
ALTER TABLE tbl ALTER COLUMN col SET NOT NULL;
ALTER TABLE tbl ALTER COLUMN col SET DEFAULT val;
ALTER TABLE tbl ADD CHECK (expr);
ALTER TABLE tbl ADD UNIQUE (col1, col2);
```
- **列位置限制**：新增列固定追加到表末尾，**PG 不支持 `FIRST` / `AFTER` 指定列位置**（调整列顺序须新建表倒数据）。
- **向非空表加 `NOT NULL` 列**：先加可空列 → `UPDATE` 赋初值 → `ALTER COLUMN ... SET NOT NULL`。
- **重命名自动传播**：表/列重命名会自动同步更新依赖视图、外键、触发器、函数与存储过程中的引用；删列会连带删除相关约束与索引（有外部视图/外键依赖须加 `CASCADE`）。

### 8.2 序列（`SEQUENCE`）与标识列（`IDENTITY`）
- **独立序列**：
  ```sql
  CREATE SEQUENCE seq_name START WITH 1 INCREMENT BY 1 [MINVALUE n | NO MINVALUE] [MAXVALUE m | NO MAXVALUE] [CYCLE | NO CYCLE] [CACHE n] [OWNED BY tbl.col];
  ```
  - 函数：`nextval('seq')`（推进并取值）、`currval('seq')`（当前会话最近一次 `nextval` 值）、`setval('seq', val, is_called)`、`lastval()`。
  - 列举全库序列：`SELECT * FROM pg_class WHERE relkind = 'S';`
- **标识列**（隐式绑定序列 `{table}_{col}_seq`，支持 `SMALLINT`/`INT`/`BIGINT`）：
  - `GENERATED ALWAYS AS IDENTITY`：禁止显式插/改值（除非 `INSERT INTO ... OVERRIDING SYSTEM VALUE VALUES (...)`）。
  - `GENERATED BY DEFAULT AS IDENTITY`：允许显式插值，**但显式插值不会推进隐式序列计数器**（后续自增可能冲突或跳步）。
  - 修改与删除：`ALTER TABLE tbl ALTER COLUMN col ADD GENERATED ... AS IDENTITY;`（列须先为 `NOT NULL`）、`SET GENERATED ... / SET INCREMENT BY 5`、`DROP IDENTITY [IF EXISTS]`。

## 九、高级文本搜索与全文检索（第 15 节）

### 9.1 模式匹配四件套
| 方式 | 运算符 | 核心特性与陷阱 |
| :--- | :--- | :--- |
| **`LIKE` / `ILIKE`** | `~~` / `~~*` / `!~~` / `!~~*` | `%`（0+字符）、`_`（1字符）；`ILIKE` 忽略大小写（PG 扩展）；`ESCAPE '$'` 转义 |
| **`SIMILAR TO`** | `SIMILAR TO` / `NOT SIMILAR TO` | **全串匹配**；混合 `%`/`_` 与正则元字符（`|`, `*`, `+`, `\d`, `\w`, `\s`）；**注意 `.` 不作通配符** |
| **POSIX 正则** | `~`, `~*`（忽略大小写）, `!~`, `!~*` | 子串匹配（需 `^`/`$` 锚定全串）；原生支持 POSIX 正则（不支持 PCRE） |

### 9.2 全文检索（Full-Text Search）
- **`tsvector`**：去停用词并词干化后的有序去重词位（lexemes）列表，含位置与权重（`A–D`）。生成：`to_tsvector('english', doc)`。
- **`tsquery`**：布尔检索式，支持 `&`（与）、`|`（或）、`!`（非）、`()` 及短语匹配 `'''sleek design'''`。生成：`to_tsquery('power & large')`。
- **匹配运算符 `@@`**：`tsvector @@ tsquery`（或 `text @@ tsquery` 隐式转换）。
- **GIN 倒排索引加速**：
  ```sql
  CREATE INDEX fts_idx ON products USING GIN ((to_tsvector('english', description)));
  ```

## 十、函数、存储过程与触发器（第 16–17、20 节）

### 10.1 用户定义函数（`FUNCTION`）
```sql
CREATE [OR REPLACE] FUNCTION func_name(p_id INT)
RETURNS TABLE(id INT, name TEXT) -- 关键字为 RETURNS（带 S）；亦可返回 VOID、标量或复合类型
AS $$
  SELECT id, name FROM products WHERE id = p_id;
$$ LANGUAGE SQL; -- 或 LANGUAGE plpgsql
```
- **避坑**：参数名**不能与函数体内引用表的列名重名**（报歧义错误）；用 `$$...$$` 或 `$tag$...$tag$` 免转义单引号。
- **重载与删除**：支持同名不同参重载；若存在重载，`DROP FUNCTION` 必须写出参数类型列表。返回 `TABLE` 时在 `FROM` 中调用（`SELECT * FROM func(1)`）拆列输出。

### 10.2 存储过程（`PROCEDURE`）
```sql
CREATE [OR REPLACE] PROCEDURE proc_name(args)
LANGUAGE SQL
BEGIN ATOMIC
  sql_1;
  sql_2;
END;
CALL proc_name(args);
```
- 使用 `CALL` 调用（而非 `SELECT`）；`BEGIN ATOMIC ... END` 保证多条 SQL 原子执行。
- **陷阱**：PG **不跟踪存储过程之间的调用依赖**，被调用过程 `B` 被 `DROP` 时不会报错，仅在运行时调用 `A` 才失败。

### 10.3 表级触发器与数据库级事件触发器
- **常规触发器**（函数须用 `plpgsql` 并 `RETURNS TRIGGER`）：
  - 内置变量：`TG_OP`（`'INSERT'`/`'UPDATE'`/`'DELETE'`/`'TRUNCATE'`）、`NEW`、`OLD`。
  - `BEFORE INSERT` 可校验/修改 `NEW` 或 `RAISE EXCEPTION` 中断写入，必须 `RETURN NEW`；`AFTER INSERT` 忽略返回值。
  - `FOR EACH ROW`（逐行触发）vs `FOR EACH STATEMENT`（每条 SQL 触发一次）。
  - 批量导数优化：`ALTER TABLE tbl DISABLE TRIGGER ALL;` → 导入 → `ENABLE TRIGGER ALL;`。
- **事件触发器（`EVENT TRIGGER`，监控全局 DDL）**：
  - 函数 `RETURNS EVENT_TRIGGER`，访问 `tg_event`、`tg_tag` 与 `pg_event_trigger_ddl_commands()`。
  - 4 个事件：`ddl_command_start`（可用于拦截非授权用户改表结构）、`ddl_command_end`（DDL 审计）、`sql_drop`、`table_rewrite`。
  - 管理视图与命令：`SELECT * FROM pg_event_trigger;`、`ALTER EVENT TRIGGER name DISABLE | ENABLE;`。

## 十一、索引类型与高级索引（第 18 节）

### 11.1 物理存储与 6 种索引类型
- 数据存放在 `<data_directory>/base/<db_oid>/<table_oid>` 8KB 堆文件页中；小表查询优化器倾向直接 `Seq Scan`。用 `EXPLAIN ANALYZE` 分析，查 `pg_indexes` 看索引定义。

| 索引类型 | 适用场景 |
| :--- | :--- |
| **B-Tree**（默认） | 等值 `=` 与范围 `<, <=, >, >=` 查询 |
| **Hash** | 纯简单等值 `=` 查找 |
| **GIN** | 多值/复合类型：`JSONB`、数组、全文检索 |
| **GiST** | 范围类型、几何空间数据、全文检索 |
| **SP-GiST** | 非平衡树结构（层级/空间数据） |
| **BRIN** | 超大表且物理存储自然有序的列，体积与维护成本极低 |

### 11.2 高级索引与仅索引扫描
```sql
CREATE UNIQUE INDEX idx_email ON users (email) NULLS NOT DISTINCT; -- PG 15+ 禁止多个 NULL
CREATE INDEX idx_lower ON products (LOWER(name)); -- 函数表达式索引
CREATE INDEX idx_expr ON products ((price * stock)); -- 非函数表达式须双层括号
CREATE INDEX idx_part ON orders (created_at) WHERE status = 'active'; -- 部分索引
DROP INDEX [CONCURRENTLY] [IF EXISTS] idx_name [CASCADE | RESTRICT];
```
- **表达式索引**：查询 `WHERE` 中对索引列做了函数/表达式运算时，普通索引会失效，必须建完全匹配的表达式索引。
- **部分索引（Partial Index）**：只索引满足 `WHERE` 条件的子集，显著减小体积与写入维护开销。
- **仅索引扫描（Index-Only Scans）**：必须同时满足 ① 索引覆盖所有查询列；② 表页在**可见性映射（visibility map）**中被标记为全部可见（`pg_class.relallvisible`）。若频繁增删改后 `EXPLAIN ANALYZE` 出现 `Heap Fetches: N > 0`，执行 **`VACUUM ANALYZE table_name;`** 后即可降为 `Heap Fetches: 0`。
- **命名避坑**：省略索引名虽会自动生成 `{table}_{col}_idx`，但可导致同一列被重复建出多个不同名的冗余索引。

## 十二、非规范化与自定义类型（第 19 节）

1. **数组（`ARRAY`）**：
   - 定义 `col TEXT[]`，构造 `ARRAY['a', 'b']` 或 `'{a, b}'`，**下标从 `1` 开始**（`col[1]`）。
   - 常用操作：`'5G' = ANY(features)`、`UNNEST(features)`（展开为行）、`ARRAY_LENGTH(col, 1)`、`ARRAY_APPEND`、`ARRAY_REMOVE`；用 `GIN` 索引加速。
2. **复合类型（`COMPOSITE`）**：
   - `CREATE TYPE coord AS (lat FLOAT, lon FLOAT);`；每张表建表时也会隐式生成同名复合类型。
   - **括号铁律**：在 `SELECT` / `WHERE` 中访问字段**必须加括号** `(loc).lat`（否则解析成表名）；而在 **`UPDATE ... SET` 中不能加括号**（`SET loc.lat = ...`）。
   - **约束缺陷**：复合类型字段本身无法直接加 `NOT NULL`/`CHECK`，须借助 **`DOMAIN`** 封装校验：`CREATE DOMAIN coord_nn AS coord CHECK ((VALUE).lat IS NOT NULL);`。
3. **枚举（`ENUM`）与 `DROP TYPE`**：
   - `CREATE TYPE mood AS ENUM ('a', 'b');`，大小写敏感且按声明顺序比较大小。支持 `ALTER TYPE ... ADD VALUE [BEFORE|AFTER]` / `RENAME VALUE`，`ENUM_RANGE(NULL::mood)`。动态变动列表建议改用外键字典表。`DROP TYPE ... CASCADE` 会连带删除依赖表列。
4. **`JSON` vs `JSONB`**：
   - `JSON` 存原始文本、保键序、允许重复键、每次读取重解析；**`JSONB` 存二进制、去重并重排键、支持 `GIN` 索引、查询快（推荐默认）**。
   - 运算符：`->` 提取对象/数组子元素（返回 `JSON`/`JSONB`），`->>` 提取为 **`TEXT`**（数组下标从 `0` 开始）。
5. **`XML`**：
   - `XMLPARSE(DOCUMENT|CONTENT ...)`、`xpath('/product/name/text()', data)` 返回 `XML[]`；可对 `CAST(xpath(...) AS TEXT[])` 建 B-Tree 索引。
6. **类型转换（`CAST` / `::`）**：
   - `CAST(val AS type)` 或 `val::type`。**`XML` 不能直接转 `NUMERIC`**，必须经 `TEXT` 链式中转：`val::TEXT::DEC`。可用 `CREATE CAST (... AS ...) WITH FUNCTION ... AS IMPLICIT;` 注册隐式转换（需 `IMMUTABLE` 函数）。
